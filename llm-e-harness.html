LLM e harness

Por que o mesmo modelo faz coisas diferentes em cada aplicativo

Uma LLM (sigla em inglês para grande modelo de linguagem: o programa treinado para escrever texto) só gera texto. Tudo o que você vê uma IA fazer, como pesquisar na web, salvar um arquivo ou acender uma luz, vem do sistema que existe em volta dela. Esse sistema se chama harness, palavra inglesa para arreio: a peça que liga o cavalo à carroça.

O modelo

Uma LLM recebe texto e devolve texto

Pense num redator terceirizado que só recebe e devolve texto por e-mail: escreve muito bem, mas não entra no seu sistema, não salva nada no seu computador e não aperta botão nenhum na empresa.

O aplicativo

Entre você e o modelo existe um sistema

Quem liga para a central de atendimento fala com a atendente, mas por trás dela há o roteiro, o sistema de cadastro e a lista do que ela pode resolver. O aplicativo parece uma conversa direta com a IA. Por baixo, existe um sistema pronto que liga o app ao modelo (no exemplo, o Opus, um dos modelos da Claude). É o harness: ele define o que o modelo pode fazer, o que não pode e quais ferramentas ele pode acionar.

O fluxo

O que acontece quando você pede uma pesquisa

É o caminho de um pedido de compra numa empresa: quem precisa escreve o pedido, o setor de compras confere se aquilo está liberado, e é ele quem compra. Siga o pedido “quem é o presidente atual da Argentina?” do seu teclado até a resposta. Repare em quem escreve texto e em quem executa.

Mesmo modelo, outras ferramentas

Mude o harness, mude o que a IA faz

Um estagiário com acesso ao sistema de pedidos emite o pedido; sem o acesso, ele só consegue dizer que não consegue. A pessoa é a mesma. Ligue e desligue as ferramentas do harness e faça o mesmo pedido de novo. O modelo é sempre o mesmo. Duas ferramentas pedem tradução: o terminal é a janela onde se digitam comandos para o computador, e “rodar os testes” é pedir a ele a conferência automática que diz se um programa ainda funciona.

    É o pedido ou é o harness?

    Quando a resposta sai errada, o reflexo é reescrever o pedido. Antes, veja em qual camada está o problema: pedido reescrito não liga ferramenta desligada nem devolve acesso que falta, e ferramenta nova não conserta pedido vago. Escolha a camada de cada caso.

    1. A IA responde que não consegue abrir a pasta compartilhada da equipe.

    2. O resumo veio no tom de relatório, com três páginas, e você queria um parágrafo para o diretor.

    3. Você pediu que a IA conferisse o próprio trabalho, e ela aprovou um texto com erro.

    Do lado do pedido, a página Prompt tem três casos em que o problema não é o pedido.

    O Claude Code por dentro

    Claude Code é outro harness

    É a mesma pessoa trocando de crachá: com o da recepção, atende visitante; com o do almoxarifado, mexe no estoque. O Claude Code também é um harness em volta de um modelo da Claude. O que muda é o que o harness oferece: ele foi feito para trabalhar dentro de um projeto no seu computador.

    Para levar

    Três ideias

    A LLM gera texto

    Só isso. Ela escreve, inclusive o pedido para usar uma ferramenta. Quem executa é outro programa.

    O harness liga tudo

    Instruções do sistema, lista de ferramentas e a ponte entre o app e o modelo. É ele que decide o que o modelo pode e não pode fazer.

    Novo harness, nova capacidade

    Quem controla o harness adiciona ferramentas sem trocar de modelo.

    LLM
    Modelo de linguagem. Recebe texto e gera texto.
    Harness
    Sistema em volta do modelo: instruções, ferramentas e a ligação com o app.
    Ferramenta
    Programa que o harness sabe executar quando o modelo pede, como uma busca na web.
    Prompt
    O texto enviado ao modelo. No app, inclui a sua mensagem e as instruções do sistema.

    Simplificação didática. Cada aplicativo monta o seu harness de um jeito, e os nomes das ferramentas nos exemplos são ilustrativos. Os números do pedido “Calcular a média” são inventados para o exemplo.
